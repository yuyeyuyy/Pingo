# Pingo 架构

Pingo 是一款本地优先的桌面学习工具。当前版本支持本地题库管理、定时学习提醒和独立答题窗口。

## 本地开发

使用 Node.js 24.14 或更新的 24.x 版本。

```sh
npm install
npm run dev
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npm start
npm run package:mac
```

`dev` 通过 electron-vite 提供 React 热更新，并监听主进程和 Preload 文件。构建产物位于 `out/`，`start` 预览该产物。Electron 首次启动时会下载相应平台的运行时。macOS 打包命令会生成当前架构的 `dist/Pingo-darwin-<arch>/Pingo.app`，供本地运行和验证。

## 五层职责

| 层             | 目录                                                               | 职责                                                                   |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Presentation   | `src/renderer`                                                     | React 显示题库、提醒设置、状态和独立答题窗口。Zustand 保存主窗口导航。 |
| IPC Bridge     | `src/preload`、`src/main/ipc`                                      | 公开最小桌面 API，集中注册 IPC Handler，验证发送方及参数并转换错误。   |
| Application    | `src/application`                                                  | 校验并编排题库操作。调度器管理提醒、学习会话和答题进度。               |
| Domain         | `src/domain`                                                       | 使用纯 TypeScript 表达题目、题库、学习会话、复习记录及提醒偏好。       |
| Infrastructure | `src/infrastructure/database`、`src/main/windows`、`src/main/tray` | 实现 SQLite、窗口、托盘、系统通知、电源事件和计时器。                  |

`src/main/index.ts` 和 `src/main/bootstrap` 组装进程生命周期、菜单和配置。 `src/shared/ipc.ts` 保存跨进程协议。表现层经 Preload API 与主进程通信，应用服务使用领域模型。领域层独立于其余模块，使用单独的 TypeScript 配置、Lint 规则和测试校验依赖。

## IPC 通信

```text
React 主窗口或答题窗口
  → window.pingo 中对应的方法
  → contextBridge
  → ipcRenderer.invoke() 使用固定通道
  → 集中注册的 ipcMain.handle()
  → 校验对应窗口、顶层 frame、页面 URL、参数数量和内容
  → 题库服务或提醒调度器 → SQLite
```

成功时，Preload 解包响应。失败时以异常通知调用者，主进程日志保留内部错误细节。题库操作在主进程校验字段、题型和题目所属题库。主窗口启用 `contextIsolation` 和 `sandbox`，关闭 `nodeIntegration`。答题窗口仅获授权读取当前会话、提交、前进和稍后提醒。主进程将状态发往对应窗口，预加载层负责订阅与清理。窗口限制页面导航和新窗口创建，生产页面使用打包内的文件和 CSP。

## 窗口与本地数据

- 主窗口通过关闭按钮或窗口菜单关闭时隐藏。再次点击 macOS Dock、选择托盘的「打开 Pingo」或启动第二个实例可恢复已有窗口。
- 「窗口」菜单和托盘均提供「开始 / 继续学习」。关闭答题窗口会跳过当前会话并保存已提交答案。
- 从应用菜单或托盘选择「退出 Pingo」会关闭窗口、移除 IPC Handler、销毁托盘并关闭数据库。
- SQLite 文件位于 Electron `userData` 下的 `pingo.sqlite`。主进程使用 Node 内置的 `node:sqlite`，避免额外原生扩展的 ABI 重编译。启动时通过事务应用迁移，使用 `PRAGMA user_version` 记录版本。第 1 版创建 `app_metadata`，第 2 版增加题库和题目表。第 3 版增加提醒状态与学习历史，第 4 版加入题库模板和四种答题形式。第 5 版增加错题和收藏数据。第 6 版加入题目难度、知识点分组、单题复习时间和题库档位。迁移保留已有题库、题目 ID 和学习历史。遇到高于当前版本的数据库时会保留文件并报错。
- macOS 专属行为位于桌面生命周期和窗口适配代码中。Windows 的窗口和托盘保留相应的 Electron 分支，当前交付以 macOS 为验证平台。

## 题库存储与导入

| SQLite 表        | 字段与约束                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| `question_banks` | UUID 主键 `id`、名称 `name` 和模板 `template`（`basic` 或 `language`）。                            |
| `questions`      | UUID 主键 `id`、外键 `bank_id`、题型 `kind`、题干 `prompt`，以及保存对应题型字段的 `content_json`。 |

`questions.bank_id` 有索引。删除题库会级联删除所属题目。列表按页读取，搜索限制在当前题库内。保存或恢复答题会话时使用题目快照。

先选择模板创建题库，再从卡片选择文件或拖入 JSON。单次导入把文件中的题目追加到指定题库。导入使用一个事务，校验或写入失败时撤销整个文件。导入窗提供可复制的 Agent 转换提示词。文件采用 UTF-8，上限 32 MiB，允许任何非空题量。顶层需要 `questions` 数组，旧文件中的 `name` 可以保留。

| `kind`            | 专有字段                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `multiple-choice` | `options`、`correctOptionIndex`（从 0 开始）。可选的 `optionExplanations` 和 `optionPartsOfSpeech` 与选项同序同长，缺失处为 `null`。释义和词性在提交后显示。 |
| `short-answer`    | 可选的 `referenceAnswer` 和 `acceptedAnswers`。提供可接受答案列表时自动判题，普通填写题可继续自评。                                                          |
| `fill-in`         | 题干用 `{{blank}}` 标记空格。 `blanks` 按空顺序提供每一空的可接受答案数组。                                                                                  |
| `ordering`        | `items` 是排序条目，`correctOrder` 是零起点的完整下标排列。会话创建时打乱条目，并保存打乱后的顺序以便续答。                                                  |

语言学习模板用可选的 `languageType` 对应词汇、句子和语法的 12 种分类，分类须匹配通用答题形式。旧题可以按其通用答题形式导入。填写和填空会统一兼容字符形式及空白，语法纠错区分大小写。查看[基础示例](./example-question-bank.json)与[语言学习示例](./example-language-bank.json)。

## 定时提醒与答题

[调度器](../src/application/reminders/scheduler.ts)在 Electron 主进程运行。它通过注入的时钟、单次定时器、存储、题目来源和桌面适配器工作。每次状态变化取消旧定时器，并按持久化截止时间安排下一次检查。较长等候最多每 5 分钟重校一次墙上时钟，休眠时取消定时器。

| 调度状态         | 进入与退出条件                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `STOPPED`        | 关闭定时提醒。用户仍可通过菜单手动学习。                                                         |
| `WAITING`        | 启用、恢复、完成或跳过后，等待一个提醒间隔。题库为空时按间隔重试。                               |
| `DUE`            | 轻提醒已到期，或重启后有未完成会话。点击通知或应用内继续会打开同一个会话，忽略通知时保留这一轮。 |
| `SESSION_ACTIVE` | 答题窗口打开。提交的答案逐题持久化。完成或关闭后退出。                                           |
| `SNOOZED`        | 暂时隐藏答题窗口，保留相同会话、题目和提交进度。到期后按当前提醒模式继续。                       |
| `PAUSED`         | 暂停期间停止自动提醒。暂停至明天按本地次日零点计算。结束或手动恢复时重新计时。                   |

默认每 30 分钟、每次 3 题，使用轻提醒。间隔以分钟保存。等待期间调整间隔会从保存时重新计时。完成最后一题并点击「完成学习」，或关闭窗口跳过时，按当时的间隔计算下一次。暂停或关闭定时提醒期间可手动答题，稍后继续的会话会随提醒恢复而重新安排。

- 主动弹窗居中、独立且不持续置顶。默认通过 Electron 的 `showInactive()` 展示。勾选允许聚焦时才主动获取焦点。
- 轻提醒使用系统通知，点击与该会话绑定。系统权限或签名导致通知不可用时，主窗口和托盘仍提供继续入口。忽略通知不会派生额外会话。
- 每日勿扰使用本地时间，支持跨午夜。到期落在勿扰时段内会推迟到时段结束并重新校验。开启空闲勿扰时，锁屏或空闲满 5 分钟会顺延一个间隔，空闲状态未知时改用轻提醒。Electron 可识别 Pingo 自己的全屏窗口，开启全屏勿扰时遇到其他应用状态未知会降级成轻提醒。
- 唤醒或重启时，保留未来的有效截止时间和未到期的暂停。过期的普通提醒从当前时间重新计时。过期的稍后提醒重新校验后最多恢复一次。重启时正在答题的会话恢复为应用内待学习，待学习通知不会重发。
- 学习策略支持随机抽题和循序渐进。会话保存题目及抽题用途的快照，题库编辑不会改变当前轮次。单选、排序、填空及带有可接受答案的填写题自动判分。普通填写题保存作答并展示可用的参考答案。

`reminder_state` 保存设置、暂停截止、下次提醒和唯一未结束会话。确认完成或关闭窗口时，`learning_history` 保存有提交记录的会话，归档与清除当前会话在同一事务。未答题目不参与判分。

## 错题本与收藏本

`wrong_questions` 与 `favorite_questions` 以原题 ID 为主键。它们通过原题归属题库，删除题目或题库会清理对应条目。已有学习历史随数据库保留，错题本从升级后的作答开始累计。

- 答错或选择「不清楚」时将题目收入错题本，连续答对计数归零。错题在任何抽题来源中连续答对两次即移出错题本。普通填写题可以在提交后自评，对未自评的答案保留待自评状态。
- 已提交的答案和错题进度在同一个 SQLite 事务更新。重复提交和重复自评不会重复累计。收藏可在练习窗口切换，收藏本也可取消收藏。
- 学习提醒可选择全部题库或单个题库，再选择完整题库、错题本或收藏本。错题本为空时回退到同一范围的完整题目，收藏本为空时本轮不打开答题窗口。
- 完整题库模式可设每第 N 轮抽错题。计数随调度状态保存，只有完成一轮才推进。跳过、稍后继续和抽不到题不会推进计数。切换题库、范围或频率时重置周期，已经开始的轮次继续使用其题目快照。

## 学习模式

第 7 版迁移增加 `study_materials`。每份资料在所属题库内有唯一的 `key`，保存标题、讲解和可选示例。`questions.material_id` 是可空外键，同一份资料可以关联多道练习题。导入 JSON 的 `materialKey` 解析为本库资料的内部 ID。导入事务先写资料，再写题目。相同资料键在同一题库内更新内容，已关联的题目继续使用该资料。参考[语言学习示例](./example-language-bank.json)。

第 8 版增加词汇选择题的题库及知识点索引。旧题缺少选项词性时，可从同题库内词和释义同时匹配的词汇题取唯一已知词性。选择题的词性和释义随会话题目快照保存，并在作答后发送。

第 9 版增加 `study_material_progress`，按题库记录学习内容的最近展示时间。语言题库按规范化的资料标题识别同一个词，基础题库使用资料键。展示资料时同步写入会话和进度。升级时从已有学习历史和当前阅读位置补记可确认的进度。

第 11 版增加 `correctly_answered_questions`，按题目 ID 保存至少答对过一次的记录。升级时从作答历史、当前会话和复习进度恢复记录。学习验证模式生成新会话时，答对过的题默认直接进练习。循序渐进会为错题池里的题重新展示关联资料。同一个词的不同题按各自的记录判断。

练习模式直接出题，旧设置默认此模式。学习验证模式在选定范围内先选没展示过的内容，每个词或知识点选一道关联题。新内容不足时，可从已学内容补足。循序渐进按题池配额抽取，随机抽题优先复习较久未展示的内容。错题本中没有带资料的题时，按原范围回退到完整题库的带资料题，收藏本保持所选范围。

纯学习模式直接从 `study_materials` 抽取资料。循序渐进优先未展示和较久未展示的内容，同等进度优先选关联题难度较低的资料。随机策略随机抽取。纯学习会话共用资料展示进度与稍后提醒流程，完成时记录资料数量。

会话保存资料内容和阅读位置。浏览资料时可稍后提醒或在应用重启后继续。提交和前进指令在服务端检查会话和当前步骤，阅读阶段的操作只更新阅读位置。作答沿用既有的判分和错题事务。

## 语言题库发音

第 10 版在题库保存学习语言，并将既有语言题库迁移为英语。答题会话在生成题目快照时保存题库语言。单词选释义题可通过 `headword` 标出题干里的目标词，旧题也可从题干中匹配词义或知识点字段记录的单词。

点击单词时，学习窗口只提交当前会话和资料位置，或题目和选项位置。主进程根据当前可见内容确定要查询的词，通过语言适配器获取录音。英语适配器使用 [Free Dictionary API](https://dictionaryapi.dev/)。音频和词典响应均限制大小与等待时间，短时缓存重复查询。其他语言可注册独立适配器。

单词选释义的选项在提交后才可请求发音，释义选单词的选项从答题开始就可播放。词典录音不可用时，答题窗口尝试使用相同语言的已安装本机语音，并保留当前作答状态。

## 渐进学习

`questions` 保存原始难度和可选知识点键。生成列 `effective_difficulty` 在缺省时按题型估算，可与题库 ID 一起查询。`question_learning` 按题目 ID 保存复习阶段、下次到期时间和最近作答时间。`bank_learning_profiles` 按题库 ID 保存当前档位、档位版本及至多十条校准样本。删除题目或题库会级联清理对应的复习记录和档位。

第 14 版将旧的第二次复习迁回复习一次，并把仍需纠错的题迁入错题池。已有回忆题保持暂停。作答事务同时保存会话、单题阶段、到期时间和错题本。结束轮次时在归档事务里更新题库档位。首次使用默认循序渐进，已有提醒设置沿用保存的策略，旧设置按随机抽题解释。详细规则见[渐进学习器设计](./LEARNING_ENGINE.md)。

第 15 版通过 `bank_learning_strategies` 保存各题库的策略，升级时沿用已有的全局策略。全部题库的混合策略保存在提醒设置中。选定的题库和对应策略在同一事务中保存，新建会话使用选定范围的策略。
